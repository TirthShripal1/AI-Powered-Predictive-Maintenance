# AI-Powered Predictive Maintenance System

A reproducible machine-learning project that predicts whether an industrial machine is likely to fail from operating-condition and sensor measurements. It compares Logistic Regression, Random Forest, and XGBoost, reports imbalance-aware metrics, saves the best model, and provides a Streamlit prediction interface.

> **Dataset note:** This repository is a clean, reproducible implementation using the public **AI4I 2020 Predictive Maintenance Dataset** from the UCI Machine Learning Repository. It is not a byte-for-byte reproduction of any earlier local/synthetic-fleet experiment. Metrics must be generated by running the included training script; no unverified scores are claimed here.

## Dataset

- Source: [UCI AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset)
- 10,000 observations; synthetic data designed to resemble industrial predictive-maintenance data.
- License: CC BY 4.0. Please cite the dataset as described in `data/README.md`.
- The project uses `Type`, air temperature, process temperature, rotational speed, torque, and tool wear as input features.
- Identifier columns and failure-mode columns are excluded. In particular, failure-mode labels are not used as predictors because they would leak target information.

The training script downloads the dataset through `ucimlrepo` when no local CSV is present.

## Quick start

### 1. Create an environment

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Train and compare models

```bash
python -m src.train
```

The script downloads the dataset if needed, performs a stratified train/test split, trains the three classifiers, evaluates them, and saves the highest-PR-AUC model to `models/best_model.joblib`. Metrics are written to `reports/model_comparison.csv`.

### 4. Launch the dashboard

```bash
streamlit run app.py
```

The dashboard requires a trained model. Run the training step first.

### 5. Generate SHAP explanations (optional)

```bash
python -m src.explainability
```

SHAP support is optional and may require a compatible version of the `shap` package.

## Evaluation

Because machine failure is a minority class, accuracy alone is not an adequate metric. The training script reports:

- **PR-AUC (Average Precision):** focuses on precision/recall trade-offs for the failure class.
- **ROC-AUC:** measures ranking quality across thresholds.
- **F1-score:** balances precision and recall at the selected threshold.
- **Precision and recall:** show false-alarm and missed-failure trade-offs.
- **Confusion matrix:** makes false positives and false negatives visible.

Use the generated `reports/model_comparison.csv` for the actual results from your run. Results can vary with library versions and the train/test split.

## Limitations

- AI4I is a synthetic dataset, not a live industrial telemetry stream.
- A model score is not a guarantee that a machine will fail; this is an educational decision-support prototype.
- Deployment in a real plant requires validation on representative equipment data, calibration, monitoring, and domain-expert review.
- The default threshold is 0.50. Operational use should tune the threshold against maintenance costs and acceptable missed-failure rates.

## Reproducibility

The split and model random states are fixed in the source code. Keep the generated metrics and dependency versions with any formal report. Do not claim results from a different dataset or experiment as results from this implementation.
